## 1. Authentication & Security Engine

### 1.1 MFA — Multi-Factor Authentication
- **Full Form:** Multi-Factor Authentication
- **What it Means:** A security mechanism that requires the user to provide two or more verification factors to gain access to a resource, rather than just a password.
- **How EOMS Works:**
  1. The user inputs their primary credentials (email + password).
  2. If verified and MFA is enabled, the server does not issue access tokens yet; it enters an intermediate challenge state (`mfa_required: true`).
  3. The user must provide a 6-digit TOTP code generated by an authenticator app (Google Authenticator, Microsoft Authenticator) or a single-use backup recovery code.
  4. Only upon successful code verification does the backend issue session JWT tokens.
- **Code Reference:** [`server/src/controllers/authController.js`](file:///c:/Users/ramch/Downloads/New%20folder/EOMS/server/src/controllers/authController.js)

### 1.2 TOTP — Time-Based One-Time Password
- **Full Form:** Time-Based One-Time Password (RFC 6238)
- **What it Means:** A temporary passcode generated using a shared cryptographic secret key and the current Unix time as inputs. Passcodes are valid for a short window (typically 30 seconds).
- **How EOMS Works:**
  1. During MFA setup, the server generates a base32-encoded cryptographic secret key and a `otpauth://` QR code URI.
  2. The user scans the QR code into their authenticator app.
  3. During login, the user submits the 6-digit code.
  4. EOMS calculates the expected code for the current 30-second time slice and checks $\pm 1$ time-step (window tolerance of 30 seconds) to account for client-server clock drift.
- **Code Reference:** [`server/src/controllers/authController.js`](file:///c:/Users/ramch/Downloads/New%20folder/EOMS/server/src/controllers/authController.js), powered by `otplib`.

### 1.3 RFC 6238
- **Full Form:** Request for Comments 6238 (Internet Engineering Task Force Standard)
- **What it Means:** The formal international engineering specification published by the IETF that defines the TOTP algorithm.
- **How EOMS Works:** EOMS adheres strictly to RFC 6238 standard parameters: HMAC-SHA1/SHA256, 30-second step intervals, and 6-digit numeric outputs.

### 1.4 Bcrypt
- **Full Form:** Blowfish Cryptographic Hash Function
- **What it Means:** A password-hashing function designed by Niels Provos and David Mazières based on the Blowfish cipher. It incorporates a salt to protect against rainbow table attacks and an adaptive cost parameter (work factor) to resist hardware brute-force cracking.
- **How EOMS Works:**
  - Passwords are never stored in plain text.
  - When a user is created or updates their password, EOMS runs `bcrypt.hash(password, 10)` (work factor 10, meaning $2^{10} = 1024$ rounds of hashing).
  - During login, `bcrypt.compare(candidatePassword, storedHash)` evaluates the credentials safely in constant time to prevent timing attacks.
- **Code Reference:** [`server/src/models/User.js`](file:///c:/Users/ramch/Downloads/New%20folder/EOMS/server/src/models/User.js), [`server/src/controllers/authController.js`](file:///c:/Users/ramch/Downloads/New%20folder/EOMS/server/src/controllers/authController.js)

### 1.5 JWT — JSON Web Token
- **Full Form:** JSON Web Token (RFC 7519)
- **What it Means:** An open standard that defines a compact, self-contained way for securely transmitting information between parties as a digitally signed JSON object.
- **How EOMS Works:**
  - **Access Token:** Short-lived (15 minutes). Carries payload claims (`userId`, `email`, `role`, `departmentId`). Signed by server secret using HS256. Frontend attaches this to HTTP headers: `Authorization: Bearer <token>`.
  - **Refresh Token:** Long-lived (7 days). Stored in the database and HTTP-only cookie. Used by the client to seamlessly request a fresh access token without forcing the user to log in again.
- **Code Reference:** [`server/src/controllers/authController.js`](file:///c:/Users/ramch/Downloads/New%20folder/EOMS/server/src/controllers/authController.js), [`server/src/middleware/auth.js`](file:///c:/Users/ramch/Downloads/New%20folder/EOMS/server/src/middleware/auth.js)

### 1.6 HS256
- **Full Form:** HMAC using SHA-256 (Hash-based Message Authentication Code with 256-bit Secure Hash Algorithm)
- **What it Means:** A symmetric cryptographic signing algorithm where a shared private secret key is used to both sign and verify the authenticity and integrity of a JWT.
- **How EOMS Works:** EOMS hashes the JWT header and payload along with `process.env.JWT_SECRET` using SHA-256. Any modification to the payload will immediately invalidate the signature.

### 1.7 Rate Limiter (Brute-Force Shield)
- **Full Form:** Ingress Request Rate Limiting
- **What it Means:** A traffic control mechanism that counts incoming requests from an IP address within a rolling time window and blocks requests exceeding a defined threshold.
- **How EOMS Works:**
  - Utilizes `express-rate-limit` on `/api/auth/login` and `/api/auth/mfa/verify`.
  - Caps requests at 5 failed attempts per minute per IP address. Exceeding attempts return HTTP `429 Too Many Requests`, preventing automated credential stuffing and dictionary attacks.
- **Code Reference:** [`server/src/routes/authRoutes.js`](file:///c:/Users/ramch/Downloads/New%20folder/EOMS/server/src/routes/authRoutes.js)

## 2. Access Control & RBAC Policy Engine

### 2.1 RBAC — Role-Based Access Control
- **Full Form:** Role-Based Access Control
- **What it Means:** An access regulation approach where permissions are granted to specific roles (e.g., `ADMIN`, `HR_MANAGER`, `IT_ADMIN`, `EMPLOYEE`), and users are assigned roles rather than individual permissions.
- **How EOMS Works:**
  - Relational mapping across 4 database tables: `Users` $\rightarrow$ `Roles` $\rightarrow$ `RolePermissions` $\rightarrow$ `Permissions`.
  - Granular permissions define operational capabilities (e.g., `employees:create`, `assets:allocate`, `documents:verify`).
- **Code Reference:** [`server/src/middleware/rbac.js`](file:///c:/Users/ramch/Downloads/New%20folder/EOMS/server/src/middleware/rbac.js)

### 2.2 TTL — Time-To-Live
- **Full Form:** Time-To-Live
- **What it Means:** A lifespan counter assigned to cached data. Once the TTL expires, the cache entry is evicted or marked stale, forcing the system to re-query the primary source.
- **How EOMS Works:**
  - In-process memory cache stores resolved role-permission sets for **60 seconds**.
  - High-traffic requests resolve user capabilities in sub-millisecond RAM access without hitting MySQL on every API call.
  - After 60 seconds, the cache refreshes from the database, ensuring administrative role updates propagate within a minute.
- **Code Reference:** [`server/src/middleware/rbac.js`](file:///c:/Users/ramch/Downloads/New%20folder/EOMS/server/src/middleware/rbac.js)

### 2.3 PEP — Policy Enforcement Point
- **Full Form:** Policy Enforcement Point (XACML standard terminology)
- **What it Means:** The architectural boundary or interceptor that intercepts a client's request to a protected resource and enforces access decisions.
- **How EOMS Works:** The Express middleware `authorizePermission(requiredPermission)` acts as the PEP. It halts unauthorized requests and returns `403 Forbidden`.

### 2.4 PDP — Policy Decision Point
- **Full Form:** Policy Decision Point (XACML standard terminology)
- **What it Means:** The evaluation engine that examines the user's attributes, role, and policies to decide whether access should be granted or denied.
- **How EOMS Works:** The resolver function in `rbac.js` looks up the user's role in the cached permission matrix, tests if `requiredPermission` is present, and returns a binary `true`/`false` decision to the PEP.

## 3. Atomic Provisioning Pipeline

### 3.1 ACID — Transactions
- **Full Form:** Atomicity, Consistency, Isolation, Durability
- **What it Means:** The four core guarantees of enterprise database transactions:
  - **Atomicity:** All operations succeed, or all fail ("all-or-nothing").
  - **Consistency:** Database transitions only between valid states respecting constraints.
  - **Isolation:** Concurrent transactions execute without cross-contamination.
  - **Durability:** Committed transactions persist even in system crashes.
- **How EOMS Works:**
  - When HR creates a new employee, EOMS initiates a single Sequelize transaction:
    1. Create account in `Users` table.
    2. Create record in `Employees` table with foreign keys to position and department.
    3. Seed standard onboarding tasks in `OnboardingTasks` table.
    4. Generate initial hardware requests in `AssetRequests` table.
    5. Write audit entry in `AuditLogs` table.
  - If any step fails (e.g. email collision or invalid position), the entire transaction rolls back (`ROLLBACK`), preventing phantom accounts.
- **Code Reference:** [`server/src/controllers/employeeController.js`](file:///c:/Users/ramch/Downloads/New%20folder/EOMS/server/src/controllers/employeeController.js)

### 3.2 Tx — Transaction
- **Full Form:** Database Transaction
- **What it Means:** A bounded sequence of database operations executed as a single logical unit of work.

### 3.3 READ COMMITTED
- **Full Form:** Read Committed Transaction Isolation Level
- **What it Means:** An SQL standard isolation level where a query within a transaction only sees data changes that were committed before the query began. Uncommitted ("dirty") reads are strictly prohibited.

### 3.4 Post-Commit Hook
- **Full Form:** Post-Transaction Event Dispatcher
- **What it Means:** An event listener pattern where external actions (such as sending emails or queuing messages) are deliberately deferred until the database transaction has successfully committed.
- **How EOMS Works:** If welcome emails or IT alerts were fired before database commit, a transaction failure would leave employees receiving emails for accounts that never existed. EOMS dispatches notifications strictly in the post-commit handler.

## 4. Hardware Asset Allocation & Concurrency Lock

### 4.1 SELECT ... FOR UPDATE (Pessimistic Row Lock)
- **Full Form:** SQL Pessimistic Row-Level Lock
- **What it Means:** A database locking clause that locks the specific rows retrieved by the query until the encompassing transaction commits or rolls back. Other concurrent transactions attempting to read or write the same row are queued or rejected.
- **How EOMS Works:**
  - When an IT technician allocates a laptop to an employee, the server executes:
    `SELECT * FROM Assets WHERE id = :id FOR UPDATE;`
  - If two IT technicians simultaneously attempt to allocate the exact same laptop to two different employees, the second transaction is forced to wait until the first finishes.
  - Once the first transaction marks the asset as `ALLOCATED`, the second transaction reads the updated state, detects the conflict, and returns `409 Conflict: Asset already allocated`.
- **Code Reference:** [`server/src/controllers/assetController.js`](file:///c:/Users/ramch/Downloads/New%20folder/EOMS/server/src/controllers/assetController.js)

### 4.2 State Machine
- **Full Form:** Finite State Machine (FSM)
- **What it Means:** A computational model consisting of a finite number of states, where transitions from one state to another are governed by explicit conditions and rules.
- **How EOMS Works:**
  - Hardware assets follow strict lifecycle transitions:
    `AVAILABLE` $\rightarrow$ `ALLOCATED` $\rightarrow$ `RETURNED` $\rightarrow$ `MAINTENANCE` $\rightarrow$ `RETIRED`.
  - An asset in `MAINTENANCE` or `RETIRED` cannot be allocated to an employee without returning to `AVAILABLE` status through formal QA checks.

## 5. Document Security, Storage & Quarantine Vault

### 5.1 MIME — Multipurpose Internet Mail Extensions
- **Full Form:** Multipurpose Internet Mail Extensions
- **What it Means:** An internet standard that identifies the nature and format of a file (e.g. `application/pdf`, `image/png`).
- **How EOMS Works:**
  - File extensions (e.g., `.pdf`) can be spoofed by attackers to hide executable malware (`malware.exe.pdf`).
  - EOMS validates both the declared MIME type and inspects magic numbers/bytes to guarantee only genuine PDFs, DOCX, and PNG/JPEG images are accepted.
- **Code Reference:** [`server/src/controllers/documentController.js`](file:///c:/Users/ramch/Downloads/New%20folder/EOMS/server/src/controllers/documentController.js)

### 5.2 SHA-256
- **Full Form:** Secure Hash Algorithm 256-bit
- **What it Means:** A cryptographic hash function that takes input data of any size and produces an immutable, unique 256-bit (64-character hexadecimal) fingerprint. Even a single bit change in the input produces an entirely different hash.
- **How EOMS Works:**
  - Upon upload, EOMS computes the SHA-256 digest of the file buffer and saves it in `Documents.file_hash`.
  - When compliance auditors review or verify the document, the file's current hash is re-computed and compared with the recorded hash to prove zero tampering or bit-rot has occurred.

### 5.3 Path Traversal Prevention
- **Full Form:** Directory Path Traversal Defense (CWE-22)
- **What it Means:** Protecting the server against directory climbing exploits where malicious inputs like `../../etc/passwd` or `..\system32` attempt to read or write files outside the intended folder.
- **How EOMS Works:**
  - Uploaded files are stripped of original client filenames.
  - Storage paths are generated using UUIDv4 random identifiers: `${uuidv4()}-${path.basename(originalName)}`.
  - File downloads resolve paths via strict canonical checks: `path.resolve(UPLOAD_DIR, sanitizedFileName)` ensuring the target remains strictly within `uploads/`.

### 5.4 Chunked Streaming
- **Full Form:** HTTP Chunked Transfer Encoding & Stream Piping
- **What it Means:** A data transfer mechanism where data is sent in small chunks as it is read from disk, rather than buffering the entire file into server RAM first.
- **How EOMS Works:**
  - When downloading large employee ID proofs or contracts, EOMS uses `fs.createReadStream().pipe(res)`.
  - This keeps the Node.js memory footprint constant (a few kilobytes) regardless of whether the file is 1MB or 500MB, preventing memory exhaustion under concurrent loads.

## 6. LMS Training Engine & SLA Scheduler

### 6.1 LMS — Learning Management System
- **Full Form:** Learning Management System
- **What it Means:** A software application for the administration, documentation, tracking, reporting, and delivery of educational courses and training programs.
- **How EOMS Works:**
  - Manages employee onboarding training modules (e.g., Company Policy, Information Security, Role Basics).
  - Tracks individual module status, quizzes, and prerequisites.
- **Code Reference:** [`server/src/controllers/trainingController.js`](file:///c:/Users/ramch/Downloads/New%20folder/EOMS/server/src/controllers/trainingController.js)

### 6.2 Blind Quiz Evaluation
- **Full Form:** Server-Side Blind Quiz Grading Engine
- **What it Means:** An exam grading design where answer keys and correct choice indicators are held strictly in server memory and database, never transmitted to the client's browser.
- **How EOMS Works:**
  - When the frontend requests a quiz, the API only delivers questions and candidate options (`{ id: 1, text: "What is MFA?" }`).
  - When the trainee answers, they submit `{ questionId: 1, selectedOption: "B" }`.
  - The server loads the correct answer, compares the answers, calculates the score percentage, and determines pass/fail status.
  - This eliminates client-side cheating via browser DevTools inspection.

### 6.3 SLA — Service Level Agreement
- **Full Form:** Service Level Agreement
- **What it Means:** A defined commitment specifying the acceptable timeframe within which a task or milestone must be completed (e.g., Day 1 tasks must finish within 24 hours of joining).
- **How EOMS Works:**
  - Every onboarding task is provisioned with a target `due_date`.
  - EOMS runs an automated scheduler (`Node-Cron`) that sweeps active tasks.
  - If `due_date < NOW()` and `status != 'COMPLETED'`, the task transitions to `OVERDUE`.
  - An automated escalation alert is dispatched to the employee's designated manager and HR coordinator.

### 6.4 Rollup Engine
- **Full Form:** Onboarding Progress Aggregation & Rollup Engine
- **What it Means:** A weighted calculation module that aggregates completions across disparate onboarding categories (documents signed, IT assets received, training modules passed, tasks checked) into a normalized 0–100% onboarding readiness score.
- **How EOMS Works:**
  - Server queries all tasks and modules associated with the employee ID:
    $$\text{Progress} = \left(\frac{\text{Completed Items}}{\text{Total Assigned Items}}\right) \times 100\%$$
  - Stored in `Employees.onboarding_progress` and updated in real-time upon any item completion.

## 7. General Architecture & Infrastructure Terms

| Term | Full Form | Meaning & Working in EOMS |
|---|---|---|
| **SPA** | Single Page Application | Web app (React + Vite) that loads a single HTML shell and dynamically rewrites the UI using client-side routing (`react-router-dom`) without full page reloads. |
| **Zustand** | Zustand State Store | Lightweight, hook-based client-side state management library used for managing authentication sessions, theme, and user preferences. |
| **REST** | Representational State Transfer | Architectural style for network applications using stateless HTTP methods (`GET`, `POST`, `PUT`, `DELETE`) with JSON payloads. |
| **CORS** | Cross-Origin Resource Sharing | Browser security mechanism that restricts HTTP requests from frontend (`http://localhost:5173`) to backend API (`http://localhost:5000`) via explicit whitelist headers. |
| **InnoDB** | MySQL InnoDB Engine | The default MySQL database storage engine providing full ACID compliance, foreign key constraints, and row-level locking. |
| **UUIDv4** | Universally Unique Identifier v4 | A 128-bit randomly generated identifier used to generate globally unique file names and session IDs without collision risks. |
